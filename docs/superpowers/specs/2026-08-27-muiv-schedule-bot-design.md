# МУИВ Расписание → Telegram: дизайн

Дата: 2026-08-27

## Задача

Каждый час проверять страницу https://www.muiv.ru/studentu/spo/raspisanie/ на новые или
изменённые файлы расписания. При изменении — скачать xlsx, распарсить, сохранить.
Ежедневно в 16:00 МСК (кроме субботы) присылать в Telegram-группу расписание на завтра
и закреплять сообщение. Группа выбирается кнопками в боте. Хостинг — Vercel, БД — Supabase.

## Установленные факты (проверено)

### JS-защита сайта

Сайт закрыт JS-защитой Bitrix. Обычный GET возвращает HTML-заглушку 13 602 байта.
Защита детерминированная и воспроизводится на сервере без браузера:

1. GET страницы → сервер отдаёт заглушку и `Set-Cookie: __js_p_=<code>,<max-age>,<sec>,<p3>,<p4>`
2. Вычислить `jhash(code)`:
   ```
   x = 123456789; k = 0
   for i in 0..1677695:
       x = ((x + b) ^ (x + x%3 + x%17 + b) ^ i) % 16776960
       if x % 117 == 0: k = (k + 1) % 1111
   return k
   ```
   (~20 мс в Node)
3. Отправить куки `__jhash_=<k>`, `__jua_=<encodeURIComponent(UA) с заменой [!'()*]>`, `__js_p_` как есть
4. Повторить запрос. Сервер отвечает 302 на тот же URL — редиректы обрабатывать вручную (`redirect: 'manual'`), иначе undici падает с `redirect count exceeded`
5. Третий запрос отдаёт настоящую страницу (~45 КБ)

Файлы (`/upload/iblock/.../*.xlsx`) закрыты той же защитой и качаются с теми же куками.
Проверено: файл скачан, 60 505 байт, `content-type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.

### Структура xlsx

Пример: `Raspisanie-kolledzh-31_5-avgusta_sentyabrya-_1-nedelya_.xlsx`

- 6 листов, по курсам: `4к 9 кл, 3к 11 кл`, `3к 9 кл, 2к 11 кл`, `2к 9 кл, 1к 11 кл`, `2к 11 кл, 2к 9 кл`, `1к 11 кл`, `1к 9 кл`
- Каждый лист: левая половина — данные, правая (начиная с колонки «День недели» второй раз) — дубликат для печати, игнорируется
- Строка 1: заголовки. `A1`=«День недели», `B1`=«Время», `C1`=«Пара», далее колонки групп.
  В одной ячейке может быть несколько групп через `\n` (например `ИСП/П-24-11\nИСП/П-23-09`) — обе привязываются к этой колонке
- Строка 2: специальность, строка 3: коды КБ, строка 4: количество студентов — не используются
- Строка 5: объединённая ячейка с датой начала недели
- Строки 6–35: шесть блоков по 5 строк = Пн, Вт, Ср, Чт, Пт, Сб
- Колонка `A` объединена по блоку и содержит «Понедельник  31.08.2026»
- `B` — время пары («8:20-09:50»), `C` — номер пары (1..5)
- Ячейка пары: `Предмет\nПреподаватель\nауд. X` (может быть длиннее — мастер-классы)
- Пустая ячейка = пары нет

Целевая группа пользователя: `ИСП/П-24-11` / `ИСП/П-23-09` — лист 1, колонка `D`.

Распаковка xlsx — через `zlib.inflateRawSync` по записям ZIP, без внешних зависимостей.
Парсинг XML — регулярками по `<row>`/`<c>` + `sharedStrings.xml` + `mergeCells`.

## Архитектура

```
cron-job.org (каждый час, :00)
   │ GET /api/tick   Authorization: Bearer CRON_SECRET
   ▼
/api/tick
   1. fetchSite() — обход защиты, список файлов + «Дата обновления»
   2. sha256 каждого файла
   3. новый/изменённый → скачать, распарсить все листы → в БД
   4. было обновление → «⚠️ расписание обновилось» во все чаты
   5. час == 16 МСК и день != суббота → расписание на завтра + pin

Telegram ──webhook──► /api/bot  (X-Telegram-Bot-Api-Secret-Token)
   /start /group /today /tomorrow /week /help
   callback_query: выбор курса → выбор группы → день недели

Браузер ──► /  — статус-страница (read-only)
```

### Модули

| Файл | Ответственность | Зависит от |
|---|---|---|
| `lib/muiv.ts` | обход JS-защиты, `getSchedulePage()`, `downloadFile()` | — |
| `lib/unzip.ts` | ZIP → `Map<name, Buffer>` через `inflateRawSync` | node:zlib |
| `lib/xlsx.ts` | xlsx buffer → `Sheet[]` (сетка ячеек + merges) | `unzip` |
| `lib/parse.ts` | `Sheet[]` → `{ weekStart, groups: {name: {day: Lesson[]}} }` | `xlsx` |
| `lib/format.ts` | `Lesson[]` → текст Telegram (MarkdownV2, экранирование) | — |
| `lib/telegram.ts` | sendMessage, pinChatMessage, answerCallbackQuery, кнопки, ретраи | — |
| `lib/db.ts` | Supabase: chats, files, schedules, logs | @supabase/supabase-js |
| `lib/log.ts` | запись событий в БД + console + алерт админу | `db`, `telegram` |
| `lib/auth.ts` | сравнение секретов без утечки по времени, проверка админа чата | `telegram` |

Каждый модуль имеет одну задачу, не знает про Telegram/Vercel сверх необходимого,
и тестируется отдельно (для `parse` — на реальном файле-фикстуре).

## Модель данных (Supabase Postgres)

```sql
chats            -- подключённые Telegram-чаты
  chat_id        bigint primary key
  title          text
  group_name     text            -- выбранная группа, null пока не выбрана
  enabled        bool default true
  pinned_msg_id  bigint          -- последнее закреплённое сообщение
  created_at     timestamptz default now()

files            -- файлы расписания с сайта
  id             bigserial primary key
  url            text unique
  title          text
  sha256         text not null
  size           int
  site_updated   text            -- «Дата обновления» как на сайте
  first_seen     timestamptz default now()
  last_seen      timestamptz default now()
  parsed_ok      bool

schedules        -- распарсенное расписание
  id             bigserial primary key
  file_id        bigint references files(id) on delete cascade
  group_name     text not null
  day_date       date not null
  day_name       text
  lessons        jsonb not null  -- [{pair, time, subject, teacher, room}]
  unique (file_id, group_name, day_date)

logs
  id             bigserial primary key
  ts             timestamptz default now()
  kind           text            -- check|file_changed|send|command|error
  chat_id        bigint
  message        text
  details        jsonb
  duration_ms    int

rate_limit
  chat_id        bigint
  window_start   timestamptz
  count          int
  primary key (chat_id, window_start)
```

RLS включён на всех таблицах, политик нет — доступ только через `service_role` с сервера.
`anon`-ключ в проекте не используется.

## Безопасность

- Секреты только в Vercel Environment Variables. В репо — `.env.example`. `.gitignore` на `.env*`
- `/api/tick`: `Authorization: Bearer <CRON_SECRET>` или `?secret=`, сравнение через `timingSafeEqual`. Без секрета — 401, ничего не выполняется
- `/api/bot`: обязательный заголовок `X-Telegram-Bot-Api-Secret-Token` == `TELEGRAM_WEBHOOK_SECRET`
- `/api/setup`: защищён `CRON_SECRET`, регистрирует webhook, вызывается вручную один раз
- Allowlist: бот отвечает только в чатах из `chats`. Добавить чат может только `ADMIN_TELEGRAM_ID` командой `/enable` в этом чате
- `/group`, `/enable`, `/disable` — только админ чата (`getChatMember`) либо `ADMIN_TELEGRAM_ID`
- Rate limit 10 команд в минуту на чат, поверх этого 30 на бота
- Скачивание: лимит 10 МБ, таймаут 15 с, проверка content-type, отказ при редиректе на чужой хост
- Никакого `eval`, никакого исполнения содержимого файла. Парсер только читает
- Весь текст из Excel экранируется для MarkdownV2 перед отправкой
- Статус-страница read-only, без секретов, без действий. Если задан `STATUS_TOKEN` — требует `?t=<token>`
- Ошибки не глотаются: пишутся в `logs` и уходят в личку `ADMIN_TELEGRAM_ID`

## Поведение бота

Единственная команда — `/start`; она открывает меню. Всё остальное делается кнопками,
каждое нажатие правит то же сообщение. В `setMyCommands` тоже только `/start`.

| Экран | Кнопки |
|---|---|
| Меню | «Завтра», «Сегодня», «Вся неделя», «Сменить группу», «Статус» |
| День | `Пн Вт Ср Чт Пт Сб`, «Вся неделя», соседние недели, «Меню» |
| Неделя | `Пн Вт Ср Чт Пт Сб`, «По дням», соседние недели, «Меню» |
| Статус | переключатель автоотправки, «Меню» |
| Выбор группы | курс → группа (с пагинацией), «Курсы», «Меню» |

Бота добавили в чат — приложение получает `my_chat_member` и сразу присылает меню:
в группе нет другой точки входа, а бот с включённым режимом приватности ничего не
показывает сам. Подключить чат этим способом может только владелец бота. Если бота
убрали из чата, автоотправка выключается. `/start` от владельца делает то же самое —
на случай, если бота добавили раньше. Смена группы и переключатель
автоотправки требуют прав админа чата.

Автоотправка: ежедневно не раньше 16:00 МСК, кроме субботы. Старое закреплённое
сообщение открепляется, новое закрепляется, под ним те же кнопки листания.

Формат сообщения (MarkdownV2, пары в цитате):

```
Расписание на завтра
📅 Вторник, 1 сентября
👥 ИСП/П-24-11

> 4. 13:45–15:15
> Стандартизация, сертификация и техническое документоведение
> Соломин М. С. · ауд. 531 ГК
>
> 5. 15:25–16:55
> Поддержка и тестирование программных модулей
> Соломин М. С. · ауд. 531 ГК

Файл обновлён: 25.08.2026
```

В режиме недели каждый день — раскрывающаяся цитата с заголовком
«Вторник, 1 сентября — 2 пары».

Под сообщением клавиатура листания: `Пн Вт Ср Чт Пт Сб`, «Вся неделя» и переходы
на соседние недели. В `callback_data` лежат даты (`d:2026-09-01`, `w:2026-09-01`),
а не индексы, поэтому кнопки не ломаются после появления нового файла.
Нажатие правит то же сообщение.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Сайт не отвечает / защита изменилась | лог + алерт админу, следующий тик пробует снова. Команды продолжают работать из кэша БД |
| Файл не парсится | алерт с деталями, автоотправка в этот день не делается — лучше молчать, чем прислать мусор |
| Telegram вернул ошибку | 3 повтора с экспоненциальной задержкой, потом лог + алерт |
| Нет данных на завтра | сообщение «на завтра пар нет» либо «файл устарел, актуального расписания нет» |
| Cron не приходил > 90 мин | статус-страница краснеет; при следующем тике — алерт о пропуске |

## Статус-страница

- Индикатор живости cron (последний чек, следующий ожидаемый)
- Текущий файл: название, размер, «Дата обновления» с сайта, sha256, когда заметили
- История обновлений (когда МУИВ менял расписание)
- Последние 50 записей лога
- Подключённые чаты и их группы
- Фирменные цвета МУИВ: тёмно-синий `#12294a`, красный `#e2001a`

## Что вне рамок (YAGNI)

- Веб-просмотр расписания (только статус)
- Личные подписки в ЛС бота
- Уведомления об изменении конкретной пары (diff по парам)
- Несколько файлов-недель одновременно — храним все, но показываем актуальную
