# Расписание колледжа МУИВ → Telegram

Бот, который каждый час проверяет [страницу расписания МУИВ](https://www.muiv.ru/studentu/spo/raspisanie/),
скачивает новый xlsx, разбирает его и каждый день в 16:00 МСК присылает в Telegram-группу
расписание на завтра — закрепляя сообщение в чате. Группа выбирается кнопками в боте.

Работает целиком на бесплатных тарифах: **Vercel** (хостинг и функции), **Supabase**
(Postgres), **cron-job.org** (часовой триггер). Своего сервера не нужно.

---

## Что он умеет

- **Часовая проверка сайта.** Считает sha256 файла. Если файл новый или изменился — скачивает,
  разбирает и сохраняет, а закреплённое расписание **молча перерисовывает**: новых сообщений
  в чате не появляется. Если закреплённого сообщения нет или правка не прошла — бот молчит,
  новое сообщение вместо правки не отправляется.
- **Автоотправка на завтра** в 16:00 МСК, кроме субботы (воскресенье — пустой день).
  Старое закреплённое сообщение открепляется, новое закрепляется.
- **Доступ по заявке.** Написать боту может кто угодно, но это лишь заявка: `/start` в личке
  создаёт её и уведомляет владельца. Пользоваться расписанием и добавлять бота в группы можно
  только после одобрения. Если бота добавили без доступа, он объясняет причину и **покидает чат**.
- **Решения — кнопками в сводке.** Владелец видит очередь заявок и жмёт «Разрешить» или
  «Отказать»; человек узнаёт о решении сам и сразу получает кнопку «Добавить в группу».
- **Владельцу бота** (`ADMIN_TELEGRAM_ID`) в меню доступна кнопка «Сводка»: сколько чатов
  подключено, какие группы популярны, сколько ошибок за сутки, когда была проверка сайта.
- **Кнопки в группе доступны всем участникам** — расписание смотрит любой. Менять группу
  и переключать автоотправку могут только админы чата.
- **Переезд группы в супергруппу** обрабатывается: при смене `chat_id` настройки
  переносятся, иначе бот замолчал бы в чате. Если бота убрали, автоотправка выключается;
  если вернули — включается снова.
- **Одна команда — `/start`.** Она открывает меню, дальше всё кнопками; каждое нажатие
  правит то же сообщение, новых не появляется. В меню команд Telegram тоже только `/start`.
- **Меню:** «Завтра», «Сегодня», «Вся неделя», «Сменить группу», «Статус». В статусе —
  переключатель автоотправки для этого чата.
- **Листание:** под расписанием кнопки `Пн Вт Ср Чт Пт Сб`, «Вся неделя» / «По дням»,
  переход на соседнюю неделю и «Меню». Точка у дня означает «пар нет», точками с двух
  сторон отмечен открытый день.
- **Оформление.** Пары лежат в цитате: номер и время жирным, преподаватель и аудитория
  курсивом. В режиме недели каждый день — раскрывающаяся цитата: видно строку
  «Вторник, 1 сентября — 2 пары», подробности открываются тапом.
- **До двух групп на чат.** В файле МУИВ две группы часто делят одну колонку, поэтому
  можно выбрать обе: в сообщении на день их расписания идут рядом, каждое со своим
  заголовком. В режиме недели показывается одна группа — две недели рядом не читаются,
  поэтому под сообщением переключатель.
- **Переименование групп подхватывается само.** Колледж меняет написание между файлами
  («ИСП/П-24-11» → «ИСП/п 24-11»), и выбор чата обновляется молча. Если же группа
  исчезла или разделилась на подгруппы, бот прямо пишет об этом, а не показывает
  «пар нет».
- **Выбор группы кнопками:** курс → группа, с галочками и пагинацией.
- **Подпись автора** в разделе «О боте» использует кастомный эмодзи из набора
  «ХакТайка». Telegram разрешает боту кастомные эмодзи, если у владельца есть Premium;
  заменить эмодзи можно, просто прислав новый боту в личку — он сохранит id и проверит
  отправкой, а при отказе оставит прежний.
- **Статус-страница** — когда МУИВ последний раз обновлял расписание, что бот с этим сделал,
  журнал последних событий, лента проверок за сутки по часам.

## Как это работает внутри

### Обход JS-защиты сайта

`muiv.ru` закрыт JS-защитой Bitrix: обычный запрос получает HTML-заглушку 13 КБ вместо страницы.
Заглушка содержит функцию `get_jhash`, которая считает хеш от числа из куки `__js_p_` и ставит
куки `__jhash_` и `__jua_`. Алгоритм детерминированный, поэтому браузер не нужен —
[`lib/muiv.ts`](lib/muiv.ts) считает тот же хеш на сервере (~20 мс) и повторяет запрос:

1. `GET` страницы → заглушка + `Set-Cookie: __js_p_=<код>,<max-age>,…`
2. `jhash(код)` — цикл на 1 677 696 итераций
3. повтор с куками `__jhash_`, `__jua_` → сервер отвечает `302` на тот же URL
   (редиректы обрабатываются вручную, иначе `fetch` падает с `redirect count exceeded`)
4. третий запрос отдаёт настоящую страницу

Файлы в `/upload/` закрыты той же защитой и качаются с теми же куками.
Весь цикл «зайти на сайт → скачать файл → разобрать» занимает **0,6 секунды**.

### Разбор xlsx без зависимостей

xlsx — это ZIP с XML внутри. [`lib/unzip.ts`](lib/unzip.ts) читает central directory и
распаковывает записи через `zlib.inflateRawSync`, [`lib/xlsx.ts`](lib/xlsx.ts) собирает
листы в сетку ячеек. Никаких внешних библиотек для Excel — меньше кода в бандле и меньше
поверхности для проблем с безопасностью.

Формат листа расписания МУИВ ([`lib/parse.ts`](lib/parse.ts)):

```
        A            B            C        D              E             …
 1  День недели    Время        Пара   ИСП/П-24-11    ИСП/Р-24-11        ← группы, по одной
 2                                     Специальность…                     на колонку; в ячейке
 3                                     КБсп 111р-24                       может быть несколько
 4                                     51                                 групп через перевод строки
 5
 6  ┌ Понедельник  8:20-09:50      1                                     ← колонка A объединена
 7  │ 31.08.2026   10:00-11:30     2                                       на 5 строк = один день
 8  │              12:05-13:35     3   Системное
 9  │              13:45-15:15     4   программирование
10  └              15:25-16:55     5   Шамова А. В.
                                       ауд. 520 ГК
11  ┌ Вторник …                                                          ← следующий блок
```

Шесть блоков по пять строк — Пн…Сб. Правая половина листа (после второго «День недели») —
дубликат для печати, игнорируется. Из одного файла получается 86 групп × 6 дней.

### Поток данных

```
cron-job.org ──каждый час──► /api/tick ──► muiv.ru ──► xlsx ──► Supabase
                                  │
                                  ├─ файл изменился → «⚠️ обновилось» во все чаты
                                  └─ 16:00 МСК и не суббота → расписание на завтра + pin

Telegram ──webhook──► /api/bot ──► Supabase ──► ответ в чат
Браузер  ──────────►  /        ──► Supabase ──► статус-страница
```

## Развёртывание

Нужно примерно 20 минут. Ниже — всё по шагам.

### 1. Telegram-бот

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → задай имя и username.
2. Сохрани токен вида `123456789:AAE…` — это `TELEGRAM_BOT_TOKEN`.
3. Ничего дополнительно настраивать не нужно: бот работает только на командах со слешем,
   а такие сообщения Telegram отдаёт даже при включённом режиме приватности.
4. Узнай свой Telegram ID у [@userinfobot](https://t.me/userinfobot) — это `ADMIN_TELEGRAM_ID`.
   На него будут приходить алерты об ошибках.

### 2. Supabase

1. [supabase.com](https://supabase.com) → New project (бесплатный тариф).
2. **SQL Editor** → вставь содержимое [`supabase/schema.sql`](supabase/schema.sql) → Run.
3. **Project Settings → API** → скопируй:
   - `Project URL` → `SUPABASE_URL`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY`

> `service_role` даёт полный доступ к БД в обход RLS. Он используется только на сервере
> и никогда не попадает в браузер. Не публикуй его.

### 3. Секреты

Сгенерируй два случайных секрета:

```bash
openssl rand -hex 32
```

Первый — `CRON_SECRET` (защищает `/api/tick` и `/api/setup`), второй — `TELEGRAM_WEBHOOK_SECRET`
(Telegram будет присылать его в заголовке, так отсекаются поддельные запросы на вебхук).

### 4. Vercel

1. Залей репозиторий на GitHub.
2. [vercel.com](https://vercel.com) → Add New → Project → выбери репозиторий → Deploy.
3. **Settings → Environment Variables** — добавь всё из [`.env.example`](.env.example):

   | Переменная | Откуда |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | @BotFather |
   | `TELEGRAM_WEBHOOK_SECRET` | `openssl rand -hex 32` |
   | `ADMIN_TELEGRAM_ID` | @userinfobot |
   | `CRON_SECRET` | `openssl rand -hex 32` |
   | `SUPABASE_URL` | Supabase → Settings → API |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API |
   | `SEND_HOUR_MSK` | необязательно, по умолчанию `16` |
   | `STATUS_TOKEN` | необязательно — закрывает статус-страницу |
   | `BOT_DESCRIPTION` | необязательно — описание в карточке бота, до 512 символов |
   | `BOT_SHORT_DESCRIPTION` | необязательно — строка под именем бота, до 120 символов |

   Если описания не заданы, код их не трогает: то, что ты поставишь через
   @BotFather, переживёт деплой. Аватарку боту в любом случае ставит только
   @BotFather (`/setuserpic`) — в Bot API такого метода нет,
   готовый логотип лежит в [`docs/logo.png`](docs/logo.png).

4. **Redeploy** — переменные подхватываются только при новой сборке.

### 5. Вебхук Telegram

Один раз после деплоя:

```bash
curl -H "Authorization: Bearer ТВОЙ_CRON_SECRET" https://ТВОЙ-ДОМЕН.vercel.app/api/setup
```

Ответ `{"ok":true,"webhook":"…/api/bot"}` означает, что бот подключён.
Проверить состояние: тот же URL с `?action=info`.

### 6. Часовой крон

Часовую проверку планирует **сама Supabase** через `pg_cron` и `pg_net` — никаких
сторонних сервисов и регистраций. Выполнить один раз в SQL Editor, подставив свои
домен и `CRON_SECRET` (готовый блок есть в конце [`supabase/schema.sql`](supabase/schema.sql)):

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule(
  'muiv-tick-hourly',
  '0 * * * *',
  $$ select net.http_get(
       url := 'https://<домен>/api/tick',
       headers := jsonb_build_object('Authorization', 'Bearer <CRON_SECRET>'),
       timeout_milliseconds := 120000
     ) $$
);
```

Проверить, что стреляет: `select status_code, content from net._http_response order by created desc;`

**Почему не иначе.** Пробовались оба очевидных варианта, и оба оказались негодны для
часовой проверки:

| Способ | Что показала практика |
|---|---|
| GitHub Actions `cron: '0 * * * *'` | бесплатный тариф выбрасывает большинство запусков: **6 за двое суток вместо 48**, промежутки до 12 часов |
| Vercel Cron на Hobby | один запуск в сутки, срабатывал стабильно, но с опозданием ~40 минут |
| Supabase `pg_cron` | стреляет по расписанию, минутная точность, входит в бесплатный тариф |

Оба запасных пути оставлены как подстраховка: [`.github/workflows/tick.yml`](.github/workflows/tick.yml)
и `crons` в [`vercel.json`](vercel.json). Лишние вызовы безвредны — проверка идемпотентна,
а отправка за день помечается в `app_state` и второй раз не уходит.

### 7. Подключение группы

1. Добавь бота в свою Telegram-группу.
2. Дай ему права администратора → **Pin Messages** (иначе не сможет закреплять).
3. Напиши в группе `/enable` — **со своего аккаунта** (того, чей ID в `ADMIN_TELEGRAM_ID`).
   Подключить новый чат может только владелец бота: так посторонние не смогут добавить
   бота к себе и жечь лимиты базы. Дальше внутри чата настройки может менять любой его админ.
4. Напиши `/group` → выбери курс → выбери свою группу.
5. Проверь: `/tomorrow`.

Первую проверку сайта можно запустить руками, не дожидаясь часа:

```bash
curl -H "Authorization: Bearer ТВОЙ_CRON_SECRET" "https://ТВОЙ-ДОМЕН.vercel.app/api/tick"
```

Чтобы сразу проверить рассылку, минуя проверку часа и дня недели, добавь `&force=1`
(параметр `secret` тоже поддерживается вместо заголовка):

```bash
curl "https://ТВОЙ-ДОМЕН.vercel.app/api/tick?secret=ТВОЙ_CRON_SECRET&force=1"
```

## Безопасность

Что сделано и почему:

- **Секреты только в переменных окружения.** В репозитории — `.env.example` с пустыми
  значениями. `.gitignore` закрывает все `.env*`.
- **`/api/tick` и `/api/setup`** требуют `CRON_SECRET`. Сравнение — через
  `crypto.timingSafeEqual`, чтобы по времени ответа нельзя было подобрать секрет посимвольно.
- **`/api/bot`** проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Без него запрос
  отбивается с 401 — даже если кто-то узнает URL вебхука.
- **Доступ по заявке.** Открыт только вход: `/start` в личке создаёт заявку. Подключить чат
  и пользоваться расписанием может лишь одобренный человек, решение принимает владелец бота.
  Бота, добавленного без доступа, не остаётся в чате — он уходит сам.
- **Ограничители поверх этого:** 10 команд и 60 нажатий в минуту на чат, автоотключение
  чатов, из которых бота выгнали, и подавление повторных алертов владельцу (одна и та же
  ошибка беспокоит не чаще раза в час).
- **Права на изменение настроек** (смена группы, переключатель автоотправки) проверяются
  через `getChatMember` — обычный участник ничего не изменит, только админ этого чата.
- **Rate limit** 10 команд в минуту на чат (20 нажатий кнопок), атомарным инкрементом в Postgres.
- **Ограничения на скачивание:** только `https://www.muiv.ru`, максимум 10 МБ, таймаут 15 с,
  проверка ZIP-подписи, отказ при редиректе на чужой хост.
- **Никакого исполнения содержимого файла.** Парсер только читает; ни `eval`, ни формул.
- **Экранирование MarkdownV2** для всего текста из Excel — кривой символ в названии предмета
  не сломает сообщение и не превратится в разметку.
- **RLS включён** на всех таблицах, публичных политик нет, `anon`-ключ не используется.
- **Статус-страница только читает.** Никаких кнопок «запустить», никаких секретов в разметке,
  `noindex`. Если задан `STATUS_TOKEN` — открывается только по ссылке с `?t=<токен>`.
- **CSP и заголовки безопасности** настроены в [`next.config.ts`](next.config.ts):
  `default-src 'self'`, `frame-ancestors 'none'`, `form-action 'none'`, шрифты
  самохостятся через `next/font`.
- **Ошибки не глотаются.** Каждая падает в таблицу `logs` и уходит в личку админу.

## Нагрузка

Замерено на боевом деплое (регион `iad1`). «Внутри функции» — собственное время
обработки, без сети до Telegram и обратно:

| Операция | Время |
|---|---|
| Обработка нажатия кнопки | **150–177 мс** |
| Запрос к Supabase | 25–85 мс |
| Вызов Telegram Bot API | 90–270 мс |
| Проверка сайта МУИВ целиком | ~2,0 с |
| Отправка расписания одному чату | ~0,27 с (при 8 параллельных) |

Рассылка идёт пачками по 8 чатов с бюджетом 45 секунд из 60, отведённых функции.
Отсюда потолок: **порядка 500 чатов за один тик**. Если чатов больше, расписание не
теряется: каждый обслуженный чат помечается датой, и следующий часовой тик продолжает
с места обрыва. День считается разосланным, только когда очередь опустела.

Что упрётся раньше всего при росте:

| Предел | Значение | Когда станет тесно |
|---|---|---|
| Рассылка за один тик | ~500 чатов | дальше расписание доедет на следующий час |
| Telegram Bot API | ~30 сообщений в секунду | при 8 параллельных выходит ~13 в секунду, запас двукратный |
| Supabase, бесплатный тариф | 500 МБ, 5 ГБ трафика в месяц | расписание занимает ~1 МБ; трафик упрётся при десятках тысяч нажатий в сутки |
| Vercel Hobby | 100 ГБ трафика | ответы бота — килобайты, запас огромный |

Отдельная мера против лишней нагрузки: запросы к Telegram **не повторяются после
ошибки 4xx**. Раньше любая клиентская ошибка уходила на три круга — в замерах
70 нажатий давали 248 обращений к API вместо 70.

Замерить самому: `GET /api/diag` с заголовком `Authorization: Bearer <CRON_SECRET>`

## Что происходит, когда что-то ломается

| Ситуация | Поведение |
|---|---|
| Сайт МУИВ не отвечает или защита изменилась | лог + алерт админу; команды продолжают работать из кэша БД, следующий тик пробует снова |
| Формат файла изменился, разбор упал | алерт с текстом ошибки; автоотправка в этот день не делается — лучше молчать, чем прислать мусор |
| Telegram вернул ошибку | 3 повтора с растущей задержкой, затем лог и алерт |
| У бота нет прав на закрепление | сообщение всё равно отправляется, в журнал пишется `skip` |
| На завтра пар нет | бот пишет «Пар нет», а не молчит |
| Крон не приходил больше 90 минут | индикатор на статус-странице краснеет |

## Разработка

```bash
npm install
cp .env.example .env.local   # заполни значения
npm run dev                  # http://localhost:3000
npm test                     # 23 теста: парсер, форматирование, время, ZIP, jhash
npm run typecheck
```

Тест парсера работает на реальном файле расписания — положи любой xlsx с сайта в
`tests/fixtures/week1.xlsx`. Без него этот тест пропускается, остальные проходят.

## Локальные проверки без базы и без Telegram

В проекте есть два дублёра, чтобы прогонять всё целиком на своей машине:

```bash
npm run fake:db    # подставной Supabase на 54321
npm run fake:tg    # дублёр Telegram Bot API на 54322
```

Затем, в третьем окне:

```bash
npm run e2e        # сайт МУИВ -> парсинг -> база -> готовое сообщение
npm run e2e:bot    # команды, кнопки, права, лимиты, автоотправка, закрепление
```

`e2e` ходит на настоящий сайт МУИВ (это нужно, чтобы проверять обход защиты),
но ничего не отправляет в Telegram. `e2e:bot` не выходит в сеть, кроме сайта МУИВ:
все вызовы Bot API уходят в дублёр и складываются в JSON, который тест проверяет.

Переменные для локального прогона:

```bash
export TELEGRAM_BOT_TOKEN=fake:token TELEGRAM_WEBHOOK_SECRET=aaaa CRON_SECRET=bbbb
export ADMIN_TELEGRAM_ID=111
export SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_SERVICE_ROLE_KEY=fake
export TELEGRAM_API_BASE=http://127.0.0.1:54322 FAKE_TG_LOG=/tmp/tg.json
```
